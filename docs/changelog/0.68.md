# 0.68 release notes

## 0.68.6 - Unreleased

- Native executable admission requires exactly one successful Cargo
  `build-finished` record as well as the selected artifact and successful process
  status. Missing, false and repeated completion records refuse admission. A
  failed Cargo exit remains primary, with its original Host execution evidence.
- Host library selection from Cargo diagnostics retries interrupted reads and
  returns invalid-data errors for impossible reader byte counts. Fragmentation,
  message bounds and successful-completion requirements remain unchanged.
- Native Cargo cancellation qualification waits for the complete `armed` marker
  instead of file creation. Both metadata and build cases start with empty and
  partial markers, retaining the existing timeout, spawn-count, cancellation,
  KILL-status and child-cleanup assertions
  ([#251 — Qualify native cancellation readiness on macOS Intel](https://github.com/dragginzgame/ic-tooling/issues/251)).
- `benchmark::try_format_marker` admits prefix/label grammar before returning a
  complete marker; Wasm `performance::try_measure` uses that admission before
  logging. `pair_benchmark_spans_by_origin` pairs only within the same prefix,
  stream, suite and label. Existing raw emission and suite/label pairing retain
  their behavior. Origins are grouping facts, not authenticated producer IDs;
  callers still keep independent producers separate where those facts coincide.
- The report example and private Wasm probe use the checked paths. Benchmark
  interruption and sampling failures request a cooperative worker stop. Workers
  finish active operations, stop scheduling and drop fixtures/server ownership;
  the driver waits and retains its primary failure and prior report. No forced
  group kill, partial report, new runtime deadline or retry is introduced.
- Native/MSRV CI uses one reviewed checkout revision with credential persistence
  disabled. MSRV compilation has a separate cache key, with writes restricted to
  main pushes and fresh archive-verification targets excluded. Successful jobs
  retain clean source revision, exact lockfile, compiler/Cargo, host and profile
  records for 14 days. Failed observers do not produce a completion marker;
  source changes (including files created during observation) and an incorrect
  MSRV compiler refuse the record. Before/after source status remains available.

Synthetic Cargo launchers used with `build_native_executable` must emit one
`{"reason":"build-finished","success":true}` record. Ordinary Cargo already
does so. Existing valid markers, CLI arguments, report fields and application
frames are unchanged. Strict marker helpers are additive; no existing caller
must switch pairing semantics, regenerate clients or reset retained state.

## 0.68.5 - Unreleased

- Native Testkit carries one admitted startup deadline through readiness and
  instance construction. Sync and async waiting retain their distinct execution
  and cancellation contracts. Baseline validation derives its stage from the
  preparation being validated, and simple native errors use the existing error
  derives without changing diagnostics or source chains.
- Build joins ordinary cache-hit/miss completion while retaining the existing
  lock scopes. Scheduled maintenance keeps its separate completion route; no
  additional guard state is introduced. Scheduled checks always return elapsed
  time internally; optional timing remains at the disabled-policy boundary.
- Benchmark reports carry named RSS measurements and accumulate the known phase
  set directly, preserving field names, null phases, ordering and statistics.
  Synthetic Cargo qualification uses a small isolated two-package workspace
  rather than copying the repository's dependency graph. Real workspace/native
  qualification remains separate from those fixtures.
- Filesystem tests share private re-execution plumbing while retaining process
  isolation for descriptor and executable-admission assertions. Response hex
  decoding consumes digit pairs after the existing complete validation pass,
  preserving size allowances, refusal precedence and fallible allocation.

Public APIs, dependency selections and feature boundaries remain unchanged.
No consumer migration, generated-client update or retained-data reset is required.

## 0.68.1 - Unreleased

### IC Wire and Platform adoption

Raise the shared `ic-wire` minimum to 0.7.2 and `ic-platform` to 0.6.15, with
matching derive/macros crates. The incoming lockfile already selected these
published packages and remains unchanged. Testkit's native adapter, private control protocol, response ownership
and encode/decode budget selection retain the existing 0.7 contract.

Wire adds opt-in host schema advice and `Packed<i8>` support. This adoption does
not change existing fields or activate a consumer schema policy. Existing schemas,
encoded frames and decoding behavior remain unchanged; no client regeneration,
persisted-byte migration or reset is required for the current callers.

Platform's native Principal/Account metadata now uses the same Wire 0.7 identity.
The existing Tooling feature selections remain unchanged; host schema producers
can select that matching metadata capability explicitly. Wire 0.7.2 changes its
own diagnostic/benchmark tooling and leaves its published runtime codec intact.

### Shared Tooling 0.26.14 adoption

Refresh the reviewed snapshot to Shared Tooling 0.26.14 at
`e14050bcc0c627f9c8a9064051699cac44fd7ab3`. Cargo-tool setup reports phases on
stderr while path output stays on stdout. Release recovery can advance from
clean manually committed candidate metadata when older tags/delivery are missing,
preserving the earlier plan and uncertainty rather than inventing completion.

Cargo-tool checks distinguish an admitted busy slot with exit status 75. The
consumer release adapter preserves that status without treating it as missing
setup or running an installer. Ordinary checks remain immediate; no hidden
wait/retry loop was added. Shared's explicit bounded read-only wait remains
available at its installer interface. Existing tool pins and own release versions
are unchanged, and this adoption performs no release or publication.

### Host and Build layering

The existing consumer-owned graph profiles now reject Wire, Testkit and known
product families beneath Host or Build, including transitive normal/build edges.
Generic Host also excludes Build; Build and generic Host exclude Platform while
Tools retains its explicitly admitted Platform profiles. Testkit's optional Wire
and private probe compositions remain permitted. The new negative fixture uses
real local Cargo graphs with aliased indirect dependencies and older published
identities, and runs in the existing tooling-command qualification target
([#250 — Enforce downward Host and Build dependencies in existing graph checks](https://github.com/dragginzgame/ic-tooling/issues/250)).

For [#249 — Keep held-fixture-only Platform capabilities out of default Testkit](https://github.com/dragginzgame/ic-tooling/issues/249),
the maintainer chose to retain the existing native dependency graph rather than
add a published support crate. Direct feature forwarding leaks Candid/management
capabilities into the all-feature Wasm graph; separate aliases for the same
Platform package are refused by Cargo even on disjoint targets. Default, CLI,
immediate-reply and held-reply native selections continue to include both the
Platform and PocketIC management DTO versions. Existing held-fixture encoding
and behavior, and the Candid-free public Wasm contract, remain unchanged.
This is a documented tradeoff, not a dependency-removal claim.

## 0.68.0 - Unreleased

### IC Wire 0.7 adoption

**Breaking:** the workspace requires published `ic-wire 0.7.0` and selects its
matching derive crate. Testkit's optional native `wire` feature exposes Wire's
`Limits` and codec errors, so consumers must select the same 0.7 API when
constructing `WireCallSpec` or matching typed causes. This is a change to
Tooling's exposed dependency and decoding semantics, requiring a minor release.
The workspace's own manifest versions stay unchanged until an authorized release.

`query_wire` and `update_wire` now require only `DeserializeOwned` responses;
request serialization and owned-response lifetimes remain unchanged. The private
performance canister's request decoder likewise drops its serialization bound.
Decode validates primitives in one pass without serializing the decoded value.
Nonminimal varints and invalid char payloads return `Malformed`; Wire removes
`Noncanonical`. Update exhaustive error matches and qualify encode/decode
budgets independently rather than relying on a second serialization charge.

Maps, sets and custom Serde visitors may normalize input. Successful decoding is
not proof that re-encoding yields the original frame or that semantic ordering
and uniqueness rules hold. Callers own those rules. The typed Testkit helpers
release the reply buffer; use raw PocketIC calls and retain original frames for
exact retries, signatures or hashes. The helpers still execute one operation
without retries and preserve application/transport failure separation.

Wire's encoder bytes and frame envelope remain unchanged. This adoption adds no
storage format, fallback codec, new dependency owner or implicit retry. Rebuild
native callers and private probe Wasms against the coordinated selection; retain
older artifacts and qualification evidence. Testkit's public Wasm library still
excludes Wire and Candid.
