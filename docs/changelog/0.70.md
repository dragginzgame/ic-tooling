# 0.70 release notes

## 0.70.4 - Unreleased

### Shared fixture deadline calculation

Native socket acceptance, HTTP request-line reads, request capture and fixture
response writes share one private remaining-deadline calculation. Each caller
retains its error type, validation and cancellation order, and partial evidence.
An expired response deadline refuses before sending any bytes. No public API,
feature, caller policy or consumer migration changes.

## 0.70.3 - Unreleased

### Smaller internal state and publication flows

Cargo grouping releases the isolated trees belonging to sealed groups; its
conservative input-order policy, exact feature equivalence and `2n−1` call bound
remain unchanged. Wasm artifact copies pair admitted source/destination lists
directly, preserving the count refusal before any copy.

Artifact-cache publication streams its manifest through the existing durable
writer. Warm verification and maximum-length admission use that same format,
counting the widest byte fields without retaining another document. Manifest
bytes, cache keys, corruption refusal and publication/cleanup errors are retained.

### Native mechanics and qualification tooling

Launch-gate pipe creation and close-on-exec setup use Rustix's owned-descriptor
APIs. Pipe versus descriptor errors, exact argv/stdin, gate release and the
reviewed post-fork operations remain unchanged. The Process package selects only
the additional native `pipe` capability of its existing Rustix dependency.

Procfs detail reads select named counters without building an owned map. They
retain the last valid duplicate, missing values, units and optional PSS selection.
Clock ticks and page size share the positive sysconf conversion while retaining
their separate caches and fallback values.

Filesystem test support supplies the common isolated-libtest runner to Build
and FS fixtures. Descriptor isolation, exact case selection, the caller's guard
and failure output remain. Testkit's graph profiles now live in a product-owned
shell script, with the same checker arguments and native/Wasm boundaries. Build
documentation describes the current coordinated Host family and module paths.
No public production API, persisted format, consumer migration, own version or
release operation changes in this batch.

## 0.70.2 - Unreleased

### Native observations and explicit workload custody

Host Process owns raw Linux procfs and Darwin libproc/Mach observations imported
from Profiler 70907ff. Process identity, CPU/waited counters, RSS, optional Linux
I/O/PSS and child-list completeness are facts, not workload adoption. Profiler
retains selection, pinned identities, cadence, retention, diagnostics and reports.
The existing bounded RSS-only table sampler is unchanged; it is not substituted
for the richer observation contract. Procfs observers accept an explicit mount
without adding automatic read budgets or selecting a workload.
The affinity query keeps one runtime interface on every host; its non-Linux
fallback has a scoped const-lint exception because Linux reads live scheduler
state. Other warnings remain denied on both native macOS architectures.

The Unix launch gate preserves stdin and exact argv; callers spawn, admit their
readiness and release the gate. OwnedChild adds explicit relinquish for callers
that intentionally keep a workload running. This releases cleanup even when its
nonblocking wait fails; it does not infer readiness or grant retry permission.
The caller owns later lifecycle/reaping. terminate_with_grace keeps the leader
unreaped until exit or caller-selected grace, then kills its group and reaps
synchronously. Existing bounded termination policies and successful handoff are
unchanged. These operations preserve Profiler's final-sample ordering and avoid
introducing an elapsed-time reap bound. Native macOS qualification is separate.

Consumers add the Host Process dependency and remove their duplicate native
mechanics; they retain their persisted DTOs and product policy. No IC dependency,
cryptographic change, default feature or canister Wasm saving is introduced.
Tracked by [#264 — Own raw process observations and Profiler workload mechanics in Host](https://github.com/dragginzgame/ic-tooling/issues/264).

## 0.70.1 - Unreleased

### IC Wire 0.7.22 adoption

The workspace now requires published IC Wire 0.7.22, matching the existing
lockfile selection for Wire and its derive package. This supplier release aligns
qualification dependencies with Platform 0.8.1; its runtime and derive source,
public APIs, protocol bytes and admission rules are unchanged from 0.7.21.

Testkit retains its optional native `wire` feature. Typed calls and private probe
controls keep their current method identities, bounds, sender selection, error
projection and one-call behavior. Wasm Testkit remains Wire-free; the private
canister probe still selects Wire explicitly. No consumer migration or retained
data rewrite is required. Workspace/package versions remain unchanged; this
adoption performs no release or publication.

The related native Platform convergence requested by
[#267 — Adopt Platform 0.8 in Testkit](https://github.com/dragginzgame/ic-tooling/issues/267)
was delivered in Tooling 0.70.0. This Wire update aligns its qualification
dependencies with that Platform boundary; it does not introduce a second
Platform identity or change Testkit's Principal API.

### Bounded Cargo grouping

Address [#266 — Bound repeated Cargo resolution in compatible package grouping](https://github.com/dragginzgame/ic-tooling/issues/266).
Build considers packages in input order and tries only the most recent group.
A conflict starts a new group rather than trying every earlier group. Including
the isolated observations, `n > 0` packages require at most `2n−1` observer calls;
the plan may contain more groups than the previous packing search. Caller-owned
target, feature, locked/offline and environment selections are unchanged.

Every candidate still runs through Cargo and must preserve each package's exact
isolated normal/build dependency tree. No metadata-only approximation or cached
observation is used. Invalid forests and missing/additional selected roots return
the typed `cargo::CargoTreeError`; observer execution failures retain their
original type and evidence. This bounds process count, not the total output
bytes or elapsed time selected by the caller. No release or publication runs as
part of this correction.

### Converged internal mechanics

Private probe endpoints carry their exported name, Wire identity and request/
response limits together. Native callers project that complete contract; the
canister's exported methods, discriminator values, framing and budgets remain
unchanged. Graph profiles forward explicit checker arguments, retaining their
package/feature/target selections and complete enabled-feature admission.

Batch maintenance carries its per-target decision separately from the original
build recipe instead of cloning the recipe to attach policy. Distinct-target
deduplication, ownership refusals, validation order, cache keys and lock ordering
remain. Baseline preparation flattens warm-success and fatal-failure handling
before the existing build/recovery path, preserving timing and both failure causes.

Ordinary group capture delegates to the existing cancellation-capable entrypoint
with the same cleanup, deadline and no-cancellation selections. Digest modes
share label ordering while retaining distinct encodings and traversal behavior.
Artifact-cache IO context and marker publication use common private mechanics,
preserving exact operations, paths, causes, marker bytes and durable-write options.
Downloader evidence selection retains primary failures when recording fails.

Filesystem test support supplies the existing native FIFO creation helper to
remaining FS, Process and Testkit fixtures, without opening either endpoint or
changing production filesystem behavior. No dependency, workspace version,
public library signature, report/cache format or consumer migration changes.

## 0.70.0 - Unreleased

### IC Platform 0.8 adoption

The workspace selects published IC Platform 0.8.1 with default features disabled.
Platform's new ledger packaging removes the registry `icrc-ledger-types` and
`icrc-cbor` dependency family. The Tools `ledger-evidence` profile now consumes
Platform's maintained generic ledger value, with the same external Candid/Serde
representation and canonical hashes. Work budgets and chain admission stay with
Tools; authenticated tips and transaction interpretation stay with callers.

This changes the public Rust identity of `LedgerBlock::block` and the value
returned by contiguous-chain verification. Construct them with
`ic_platform::icrc_ledger_types::Value` from Platform 0.8.1, rather than the old
registry ledger type. Likewise, consumers exchanging the owned Registry
`ic_platform::Principal` must use the same Platform 0.8 identity. Recompile
consumers together; no data rewrite, hash change or request replay is required.

Registry selects only Platform's owned `principal` capability. Consumers needing
external SDK conversions explicitly select Platform's `principal-external`
feature. Registry's byte/interval tests exercise its owned principal without
pulling external conversions into that profile. Testkit selects
`principal-external` directly, preserving `fake_principal` and PocketIC's existing
external Principal identity on native and Wasm targets without adding Candid to
the Wasm profile. Testkit's native client and management feature selections stay
the same, and the private probe keeps its existing CDK/runtime selection.

The lockfile removes seven obsolete packages, including the registry ledger,
CBOR and older macro dependencies. Dependency graph checks enforce the new
ledger package exclusions. The shared snapshot, workspace version, Rust edition,
MSRV and simulator selection are unchanged. No release or publication is part
of this adoption; native macOS qualification is separate from local Linux checks.
