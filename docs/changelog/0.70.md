# 0.70 release notes

## 0.70.1 - Unreleased

### Native observations and explicit workload custody

Host Process owns raw Linux procfs and Darwin libproc/Mach observations imported
from Profiler 70907ff. Process identity, CPU/waited counters, RSS, optional Linux
I/O/PSS and child-list completeness are facts, not workload adoption. Profiler
retains selection, pinned identities, cadence, retention, diagnostics and reports.
The existing bounded RSS-only table sampler is unchanged; it is not substituted
for the richer observation contract. Procfs observers accept an explicit mount
without adding automatic read budgets or selecting a workload.
The affinity query keeps one runtime interface on every host; its non-Linux
fallback has a scoped const-lint exception because Linux reads live scheduler
state. Other warnings remain denied on both native macOS architectures.

The Unix launch gate preserves stdin and exact argv; callers spawn, admit their
readiness and release the gate. OwnedChild adds explicit relinquish for callers
that intentionally keep a workload running. This releases cleanup even when its
nonblocking wait fails; it does not infer readiness or grant retry permission.
The caller owns later lifecycle/reaping. terminate_with_grace keeps the leader
unreaped until exit or caller-selected grace, then kills its group and reaps
synchronously. Existing bounded termination policies and successful handoff are
unchanged. These operations preserve Profiler's final-sample ordering and avoid
introducing an elapsed-time reap bound. Native macOS qualification is separate.

Consumers add the Host Process dependency and remove their duplicate native
mechanics; they retain their persisted DTOs and product policy. No IC dependency,
cryptographic change, default feature or canister Wasm saving is introduced.
Tracked by [#264 — Own raw process observations and Profiler workload mechanics in Host](https://github.com/dragginzgame/ic-tooling/issues/264).

## 0.70.0 - Unreleased

### IC Platform 0.8 adoption

The workspace selects published IC Platform 0.8.1 with default features disabled.
Platform's new ledger packaging removes the registry `icrc-ledger-types` and
`icrc-cbor` dependency family. The Tools `ledger-evidence` profile now consumes
Platform's maintained generic ledger value, with the same external Candid/Serde
representation and canonical hashes. Work budgets and chain admission stay with
Tools; authenticated tips and transaction interpretation stay with callers.

This changes the public Rust identity of `LedgerBlock::block` and the value
returned by contiguous-chain verification. Construct them with
`ic_platform::icrc_ledger_types::Value` from Platform 0.8.1, rather than the old
registry ledger type. Likewise, consumers exchanging the owned Registry
`ic_platform::Principal` must use the same Platform 0.8 identity. Recompile
consumers together; no data rewrite, hash change or request replay is required.

Registry selects only Platform's owned `principal` capability. Consumers needing
external SDK conversions explicitly select Platform's `principal-external`
feature. Registry's byte/interval tests exercise its owned principal without
pulling external conversions into that profile. Testkit selects
`principal-external` directly, preserving `fake_principal` and PocketIC's existing
external Principal identity on native and Wasm targets without adding Candid to
the Wasm profile. Testkit's native client and management feature selections stay
the same, and the private probe keeps its existing CDK/runtime selection.

The lockfile removes seven obsolete packages, including the registry ledger,
CBOR and older macro dependencies. Dependency graph checks enforce the new
ledger package exclusions. The shared snapshot, workspace version, Rust edition,
MSRV and simulator selection are unchanged. No release or publication is part
of this adoption; native macOS qualification is separate from local Linux checks.
