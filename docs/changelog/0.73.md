# 0.73 release notes

## 0.73.0 - Unreleased

### Platform identity and consumer migration

The workspace adopts published IC Platform 0.13.0, including its coordinated
macros and runtime guard. Tools exposes Platform-owned registry principals;
consumers exchanging these values must align direct `ic-platform` dependencies
to 0.13 and rebuild together. This public dependency identity change selects a
coordinated workspace minor even though method paths and stored bytes are unchanged.

Platform 0.13 removes the gzip facade and its Host Artifacts dependency, eliminating
the native Platform-to-Tooling bootstrap edge. Tooling already uses artifact codecs
directly, so no caller conversion is needed. Other selected facade Rust sources
match 0.12. Existing feature selections, runtime
ownership, native external-protocol adapters and Wasm exclusions remain intact.

The workspace also adopts published Wire 0.11.0 and its matching derive crate.
Testkit exposes Wire's `Limits` and typed codec errors, so callers must align
direct Wire dependencies to 0.11 when supplying limits or matching those errors.
Wire's core codec sources match 0.10.0; frame bytes, admission budgets, method
identities, one-call/no-retry behavior and original error causes remain intact.
This supplies the local adoption requested by
[#274 — Align Testkit typed Wire calls with the Platform 0.12-compatible Wire release](https://github.com/dragginzgame/ic-tooling/issues/274).
The compatible Tooling release still needs publication before downstream
consumers can select this new public type identity.

Wire 0.11's optional `platform-types` and `endpoint` integrations target Platform
0.12 and remain disabled here. They do not supply schemas for Platform 0.13's
owned identities. This workspace uses the core codec, which adds no second
Platform identity; Testkit's canister library graph remains Wire-free. Consumers
needing optional Platform integration must select a compatible published supplier.

### Qualification and dependency ownership

Build's fake Cargo producer reuses the standard native `CARGO` environment value
instead of requiring a separate fixture variable. Tests that replace the complete
child environment therefore retain executable selection and reach their intended
metadata/build/error checks. The production environment-replacement contract and
native path handling are unchanged.

Testkit delegates exact scaled integer averages to published Metrics 0.22.0,
with default features disabled. Zero-denominator precedence, floor rounding,
full-width totals, representable results despite intermediate overflow, and
typed final-overflow errors retain their existing Testkit contract. Grouped
counter admission and atomic updates remain Testkit-owned. Metrics' native Wire
metadata and recording features stay disabled; normal Testkit adds no Wire edge,
and Host/Build still exclude Metrics. This resolves the implementation in
[#268 — Delegate Testkit scaled benchmark averages to ic-metrics](https://github.com/dragginzgame/ic-tooling/issues/268).

The Wasm dependency family now selects encoder/parser 0.263 and Wat 1.263,
retaining one encoder identity with held-reply fixtures. Validation and text
compilation remain separate opt-in capabilities; no graph exception or component
feature was added. Wat stays within the 1.263 patch line so an ordinary Cargo
update cannot independently select the next encoder family. Existing incoming
Wat and unrelated lock updates are retained
while redundant 0.262 encoder/parser packages are removed. This resolves
[#275 — Keep Wat and direct Wasm encoder selections in one graph identity](https://github.com/dragginzgame/ic-tooling/issues/275).

Native CI runs publication admission and its full workspace lint gate once,
then the dry run and remaining offline CI checks. Standalone CI and publication
commands retain their independent full gates; no bypass flag or reusable lint
receipt is introduced. Public package selection and provenance policy stay
consumer-owned through the existing lower-level Shared publication runner.

The private development driver's direct Wire dependency is needed only by tests
and is now a dev-dependency. Platform remains a production dependency for workload
limits. Build carries its admitted exact/shared Cargo target into the build path
without reinterpreting the original cache mode, preserving lock coordination.

Cargo workspace discovery retains its typed execution error. Fake Cargo fixtures
forward the real executable through a native environment value, preserving paths
that cannot be represented as UTF-8. Candid parsing keeps its existing display
and intentionally terminated public source chain while using the shared error
derive convention.

### Server diagnostics and published consumer alignment

`ic_testkit::pic::pocket_ic_server_requirement()` supplies the human-readable
stable server range used by startup and the development driver. The exact
provisioning pin remains independent of protocol admission.

The convergence requested by
[#270 — Adopt Platform 0.9 and Wire 0.8 in Testkit](https://github.com/dragginzgame/ic-tooling/issues/270)
and [#271 — Align published Testkit Wire call contracts with Wire 0.8](https://github.com/dragginzgame/ic-tooling/issues/271)
shipped in 0.71.0; the published 0.72 family advances those public identities to
Platform 0.11 and Wire 0.10. These supplier issues are now closed. Consumers must
align direct Platform/Wire dependencies to their chosen Testkit minor; no field
conversion or transport copy is needed.
