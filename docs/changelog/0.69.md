# 0.69 release notes

## 0.69.8 - Unreleased

### Explicit custody and complete results

Durable file publication holds each staging descriptor together with its sibling
name and parent descriptor through verification, publication and explicit
cleanup. Panic retention, read-only handoff, replacement detection and
before/after-publication error handling retain their existing behavior. Writer
errors use derived source forwarding while preserving their cleanup-aware
display and both direct and generic boxed source identities.

Baseline acquisition attaches final timings when constructing the returned
error, after preparation, stale teardown and any permitted recovery have ended.
Both primary and recovery causes remain available through the existing error
variants. Benchmark summaries require their main measurements before publication
and printing; absent optional phases still encode as null and successful report
fields and statistics keep their existing representation.

Depfile parsing models its three rule states directly, and reading collects
paths in one flow without a mutable output parameter. Cargo escapes, phony rules,
generated-root exclusions and refusal order remain unchanged. Exact-cache locking
shares its silent and observed implementation, and shared-target inspection and
maintenance reuse size/use-time observation with their original diagnostics.
Wasm record completion receives reporting fields without publication authority.
Build's lock fixtures share private process-isolation scaffolding.

This is compatible internal cleanup. Public APIs, dependency/feature boundaries,
artifact identities and recovery formats remain unchanged; consumers need no
migration or new tool selection.

## 0.69.7 - Unreleased

### Build observations and lifecycle handling

Cargo configuration traversal keeps its observed files, active include paths
and remaining limits together. Native executable discovery keeps message
selection and completion state together, while retaining its strict protocol
admission and streaming diagnostics. Package qualification groups the retained
input observations with their final revalidation, preserving observation order,
mutation rejection and retained evidence. Wasm failures use the phase recorded
by acquisition rather than inferring it again from the returned error.

PocketIC readiness, instance construction and command supervision share their
server liveness check. Each caller still owns its original cancellation and
cleanup behavior. Benchmark report publication shares handling of failures
before publication while retaining successful publication with a durability
warning. Benchmark callers can inspect worker status and identity without
access to the underlying child process.

Public signatures, error-source identity, feature boundaries, artifact formats
and consumer-owned policies remain unchanged. No consumer migration or workspace
version bump is required by this compatible cleanup.

## 0.69.6

### Portable package source inventory

Fix [#262 — Fix macOS source-inventory mode compilation](https://github.com/dragginzgame/ic-tooling/issues/262):
the source inventory now keeps Rustix's native mode type instead of assigning
Darwin's 16-bit mode bits to a 32-bit field. A typed permission mask still selects
only `0o777`; serialization emits the same numeric JSON mode and preserves the
existing evidence field order. The regression coverage includes special mode bits
and compares the complete encoded inventory against the former representation.
This is a compatible correction to IC Build 0.69.5; no consumer API, artifact
format or permission-policy migration is required.

### Batch observations and bounded host paths

Batch input resolution shares successful workspace manifest/lockfile observations
within its metadata context. Nested-workspace declaration observations are reused
within one hashing pass, while each specification still derives exclusions from
its own roots and declared sources. Failed reads are not cached. New acquisitions
and mutation guards use fresh contexts; caller-owned source custody, fingerprint
formats and publication/invalidation locks remain unchanged. This reduces repeated
TOML parsing and declaration reads without introducing another public cache mode.

Staged and cached artifact output inspection share their declared-output
projection and error wrapping. Staging still collects invalid outputs, cached
lookup still treats invalid outputs as misses, and directory-read failures retain
their original error behavior. Cargo execution tests use the existing shared
artifact-message scaffold while retaining their explicit target and manifest.

Process communication reuses one scratch buffer for stdout and stderr reads.
Directory size observation queues only directories and immediately accounts for
non-directory metadata, retaining symlink lengths, saturating totals and native
I/O errors. JSON response decoding borrows ordinary response hex and owns escaped
text, avoiding a complete intermediate copy for unescaped responses. Duplicate
fields, malformed JSON, hex checks and independent byte allowances remain strict.

Focused Linux measurements support lower batch-discovery cost and lower peak
memory for wide directory trees and large JSON replies. They are not whole-build
or deployment speedup claims. Three experiments were left unchanged: progress
rendering was slower, snapshot indexing slowed common small batches, and selective
status parsing would weaken existing numeric JSON admission unless given a more
complex validator. No consumer migration, feature change or workspace version
bump is required by this compatible batch.

### Upstream dependency adoption

The root catalog now requires Platform 0.7.2 and Wire 0.7.19, matching the already
selected lockfile packages and their macro/derive companions. Existing inherited
dependency declarations, optional feature boundaries and Rust 1.91 support remain
unchanged. No other dependency or tool selection changes.

Wire adds caller-storage encoding and accepts Serde crate-path attributes without
changing existing frame bytes or requiring consumer schema migration. Existing
Testkit calls keep their owned byte buffers because the PocketIC transport consumes
them. Platform adds DER framing admission in its optional signature integration;
that feature remains disabled here. Its Candid change documents the existing Wasm
nesting limitation rather than changing decoder behavior. Existing caller limits,
source provenance and supplying-owner qualification obligations remain in force.

## 0.69.5

### Bounded host paths and fixture cleanup

Complete newline frames can borrow their input during delivery; fragmented
frames grow reusable scratch amortized across chunks. Inclusive byte limits,
overflow prefixes, EOF policy and terminal callback failures remain unchanged.
The bound applies to retained bytes, not allocator capacity. Table rendering
retains each escaped cell's scalar display width for padding instead of scanning
it again, at the cost of one extra width value per cell. Rendered bytes and
terminal escaping remain unchanged.

Reusable input digests are indexed by exact input path, retaining their domain,
label, exclusion and traversal checks. Hash domains, framing, source custody
and cache fingerprints are unchanged. Host FS can hash an already-held Unix
descriptor without duplicating its handle. Tree checksums and Cargo source
inventory use that operation; it advances the shared offset and retains the
canonical inclusive byte limit and overflow probe. Path admission remains with
the caller. Durable writers retain their explicit synchronization.

The private benchmark driver captures provenance in a typed serializable record
instead of a dynamic JSON tree, retaining the existing report schema and
pre-worker admission. Startup test scripts share their ordinary spawn
configuration while keeping each timeout and special TTL/output case explicit.
Observing tree visitors can use a default no-op directory completion callback;
writers still override it when finalization matters.

Focused Linux microbenchmarks supported the fragmented-frame, Unicode-table,
large warm-digest-cache and small-file descriptor changes. These are not whole
build or server speedup claims. Scratch reuse for report distributions and an
artifact-target index did not justify their complexity for the measured common
cases. Borrowed Cargo recipe rendering would require another representation or
a broader specification migration without a demonstrated build-time benefit;
those three paths retain their existing implementations. No consumer migration
or workspace version change is required by this compatible batch.

## 0.69.3 - Unreleased

### Startup and acquisition decisions

Sync and async startup share one remaining-budget/poll-interval calculation.
Owned servers still receive periodic liveness checks; borrowed servers retain
their external ownership and complete instance-creation deadline. Waiting,
cancellation, panic capture and cleanup remain specific to each execution path.
The CLI explicitly selects a configured environment, supplied directory or
default bundle, preserving conflict diagnostics and spawn-only option admission.

Built and reused artifact acquisitions share usage recording, scheduled
maintenance, final timing and retained record construction. Input revalidation,
publication, materialization and lock custody keep their existing order. Batch
maintenance admission owns conflicting-policy rejection and target deduplication
together, preserving per-entry specification failures and collect-all behavior.

Wasm target admission and captured output projection have a dedicated private
owner. Generic source discovery no longer implements cdylib selection, output-name
collision checks or target-kind projection inline. Snapshots still retain that
projection or its error: the existing borrowed `artifact_paths()` API reads the
captured result without new Cargo/filesystem observations, and non-Wasm input
evidence remains usable. No public type/path, fingerprint framing, artifact stamp,
retained manifest or dependency selection changes.

## 0.69.2 - Unreleased

### Execution and fixture simplification

Process custody records owned, reaped and lost states together, retaining the
original bounded-reap allowance on repeated cleanup failures. Capture,
communication and drain operations select their private behavior by name.
Wasm acquisition admits cache/maintenance combinations once before execution;
lock ordering, post-lock revalidation and retained cache representations stay
unchanged. Generic Cargo observations no longer depend on Wasm orchestration,
while the existing public observation type and path remain available.

Baseline-pool acquisition finalizes total timing and successful outcomes in one
place. Fatal restore failures still discard the partially changed instance;
recoverable failures retain one rebuild attempt and both causes if it fails.
Native fixtures share bounded Unix process-state observations and a readable
fake downloader prefix, keeping zombie/reaping distinctions and each deliberate
failure control at its caller.

### Tooling admission

The hook fixture derives transitive companions from explicit roots instead of
maintaining another consumer file inventory. The snapshot is committed Shared
revision `d08cbcafbaff4227e798a890232e2248bf167504` (0.27.1 plus the fixture
correction in [Shared #318](https://github.com/dragginzgame/shared-tooling/pull/318));
upstream acceptance and release remain separate. It also includes the supplying
owner's advisory-tracking guidance, without changing dependency or security gates.

CI keeps one execution of each Make, release, publication and qualification-record
suite under the relative/aliased temporary-directory proof. Standalone commands
remain available. Retention probes still cover every selected fixture, including
premature success and failure exits; the shared source-prefix injector remains
because it stops before executable setup/publication effects without adding a
second test-execution framework. Package versions and consumer setup pins stay
unchanged.

## 0.69.1 - Unreleased

### Streaming gzip consumers

[#260 — Support bounded gzip readers for streaming Cargo archive inspection](https://github.com/dragginzgame/ic-tooling/issues/260).

`artifact::with_gzip_reader` accepts a caller-owned buffered source and inclusive
compressed/expanded budgets. A synchronous callback receives only `Read`, so a
pull parser can inspect a staged file without retaining either complete payload.
After callback success, Tooling drains the remaining bounded member, validates
CRC/length, and refuses trailing bytes or another member before admitting the
result. Source IO, decoding, both limits and typed consumer errors stay distinct.
An observed stream failure cannot be hidden by a callback returning success;
consumer failure returns without unnecessary draining.

Compressed accounting bounds bytes exposed to the decoder; caller buffer
read-ahead and blocking deadlines remain caller-owned. Exact-limit EOF probes
do not turn the owner's budget into artificial source EOF. The supplied reader
must represent the complete logical input; a caller-truncated view cannot prove
EOF of its underlying file/transport. Existing slice APIs
share this completion engine while retaining eager input admission and their
existing public error types. This adds no filesystem, tar, staging, publication
or rollback policy. Consumer observations remain provisional until completion.

### Gzip ownership

- Keep gzip encoding in `ic-host-artifacts::artifact::encode_gzip`; no Platform
  feature or dependency migration is needed. Ordinary artifact and native HTTP
  fixtures delegate to this bounded encoder at fast level 1. The HTTP case needs
  a small compressed payload, not a particular compressed representation; its
  decoded-byte limit and partial-body assertions remain unchanged. Tests of exact
  production bytes/hashes or compression-sensitive product limits retain their
  product settings.
  The HTTP selection remains dev-only, preserving its compression-free normal
  dependency graph. The direct-dependency policy admits `flate2` only in Artifacts.
- Retain independent backend byte-equivalence controls and a deliberately
  noncanonical optional-header fixture at the codec owner. Consumers keep product
  levels, staging/publication policy and retained compressed-byte obligations;
  zero timestamps do not promise identical bytes across dependency/backends.

### Mutable instance access

`PocketIcInstance::instance_mut()` borrows the client exclusively while its
managed server remains owned by the wrapper. Consumers can call mutable native
setup APIs such as `PocketIc::make_live` without using `into_parts()` and
maintaining teardown ordering themselves. Replacing the client explicitly retains
the caller's responsibility for the old client's server lifetime.
Existing ownership, drop order and server selection are unchanged.
[#257 — Expose mutable client access while retaining PocketIcInstance server custody](https://github.com/dragginzgame/ic-tooling/issues/257).
Auth adoption remains tracked in [Auth #90 — Consolidate admission policy and simplify client and qualification state](https://github.com/dragginzgame/ic-auth/issues/90).

### Shared Tooling adoption

Adopt Shared Tooling 0.26.26 through the canonical exporter. The standard Rust
formatter reports manifest sorting and Rustfmt progress with elapsed time and
reuses successful results only for unchanged inputs after prepared-tool checks.
Use `make fmt-check FORMAT_RUST_ARGS=--no-cache` to run every pass explicitly.
Failed formatter logs remain retained. The consumer's hook fixture carries the
new driver; its substituted-Cargo Make fixture exercises every pass without
pretending to qualify input reuse. Tool pins, library APIs and MSRV are unchanged.
This workspace's explicit Rust module paths conservatively disable the shortcut,
so its actual formatting selection still runs all passes.
The shared gzip policy matches the artifact-owner consolidation above.
Formatting hooks now preserve opaque submodule identities without exporting child
contents. The driver also supports explicitly selected standalone Rust sources
and editions; this workspace keeps its existing Cargo-owned formatter selection.
The governance snapshot includes the linked Node prerequisite guide without
activating Node setup. No runtime scanner or new dependency is introduced.
The formatter uses the shared Rust lexer to inspect balanced attributes instead
of matching unrelated later path text. Actual module-path overrides and incomplete
syntax still select uncached execution. The lexer is exported with the driver
and included in the consumer's hook and release-routing fixtures. The selected
source's canonical version now agrees with its 0.26.26 release notes.

## 0.69.0 - Unreleased

### Breaking changes and migration

- Raise the workspace's IC Platform requirement to 0.7.0 and select matching
  Platform/macros releases. Host Tools' Registry shard APIs expose Platform's
  owned `Principal`; the 0.7 package defines a distinct Rust type from 0.6 even
  though its bytes and behavior are unchanged. Consumers exchanging those values
  must select Platform 0.7 alongside Tooling 0.69. The coordinated Tooling release
  therefore needs a minor increment. Repository package versions remain unchanged
  until release preparation.
- Platform retires Candid JavaScript/TypeScript compiler exports and the
  compiler-only merged-program helper. Tooling uses none of those exports;
  required external Candid service parsing, type checking and bounded decoding
  remain in their existing owners. No endpoint regeneration, stored-data reset,
  wire-format migration or feature activation is required by this adoption.

### Development policy

- Adopt Shared Tooling 0.26.22 through the canonical exporter. The reviewed
  policy requires Wire for owned application payloads, isolates required Candid
  at named external or retained-data boundaries, and uses existing native error
  derives where their contracts match. Source inspections, machine-output
  decoding, bounded subprocess capture and terminal diagnostics retain their
  independent admission and negative-test obligations. This snapshot updates
  policy documents; tool pins, executable scripts and CI wiring are unchanged.
  Adopting the rules does not add executable enforcement.
