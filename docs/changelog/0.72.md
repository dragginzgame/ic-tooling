# 0.72 release notes

## 0.72.0 - Unreleased

### Coordinated Platform and Wire adoption

The root catalog and lock select IC Platform 0.11.1 with its coordinated macros
and runtime guard. Existing feature selections stay unchanged: Tools opts into
its selected native capabilities, Testkit's canister side uses IC0, and the
private probe selects the embedded runtime.

Tools' registry functions expose Platform's owned `Principal`. Its dependency
identity changes, so consumers passing these values must update direct
`ic-platform` dependencies to 0.11 and rebuild together. Public method paths,
stored formats and protocol bytes are unchanged. Testkit's external principal
and stable-memory trait boundaries retain their upstream identities.

Platform now owns prepared one-shot calls under `ic_platform::call`. This
workspace did not use the retired `ic-call` package; no import rewrite or new
runtime feature is needed here. Host/Build layering, Candid exclusions on Wasm,
and the single runtime owner policy remain in place.

### Wire schemas and dependency direction

The root catalog and lock select IC Wire 0.10.0 and its matching derive crate.
Wire's optional endpoint integration now aligns with Platform 0.11; Tooling
continues to use the native codec and private probe without enabling that
integration. Existing Wire feature, protocol and admission boundaries remain.

Platform removes its production Wire dependency and the `wire-schema` feature.
Consumers needing Wire schemas for Platform-owned Principal/Account types must
select Wire's `platform-types` instead. That integration points from Wire to
Platform and does not enable the runtime; only `endpoint` selects the CDK.
This workspace does not use the retired feature or need the optional schemas,
so its existing feature selections remain unchanged.

Testkit's public request/response limits and typed codec-error fields carry Wire
0.10 dependency identity. Callers constructing `WireCallSpec` or matching those
causes must align their direct `ic-wire` dependency to 0.10. Native frame bytes,
method identities, accepted inputs and resource bounds are unchanged.
