# 0.71 release notes

## 0.71.0 - Unreleased

### Platform and Wire adoption

IC Platform 0.9.1 owns its IC system-call and executor implementation. Testkit's
Wasm graph therefore excludes the external `ic0` and `ic-cdk-executor` packages;
the private performance probe selects Platform's embedded executor. Existing
native/Wasm and codec feature boundaries remain in place.

The executor singleton guard is selected only with Platform's executor/runtime
features. The private probe requires that internal guard; Host/Tools and Testkit's
IC0-only Wasm profile exclude it. Non-runtime consumers can coexist with another
executor without claiming runtime ownership.

Platform's owned public types have a new dependency identity. Consumers exchanging
Platform values with Tools, including registry principals, must align their direct
Platform dependency to 0.9 and rebuild together. No persisted-format migration is
introduced by this adoption. Testkit's upstream external-principal boundary stays
unchanged.

IC Wire 0.8.0 is selected for typed calls and the private probe protocol. Testkit's
public limits and codec-error fields now have Wire 0.8 dependency identity;
callers constructing `WireCallSpec` or matching those causes must align their
direct `ic-wire` dependency to 0.8. The native codec, protocol bytes and admission
rules are unchanged. Wire's endpoint integration now uses Platform 0.9; Tooling
does not enable that optional integration and retains its existing probe runtime.

### Shared rules and fixture ownership

Shared Tooling 0.27.11 is adopted at
`62edfbd43087a718bf0283e9040676a49211976d`. Build's `test-support` feature
exposes its shared fixture scaffolding through ordinary modules; default consumers
do not enable it. Integration targets using Build helpers explicitly require that
feature; Make/CI already select it through `--all-features`. There is no self dev dependency, so
Cargo packaging does not resolve unpublished fixture features from an older
registry copy. Focused integration runs using shared helpers must enable
`test-support`; the separate CLI integration target still requires only `cli`.
Generated flag probes declare their custom cfg names explicitly. Lint exceptions
use checked expectations where all maintained configurations permit them; retained
allowances explain the configuration or MSRV constraint.

### Converged artifact graph checks

Artifact package exclusions/counts and effective feature assertions consume one
Shared Tooling observation per selected profile. The Wasm, encoding and text
profiles retain their package rules, validator/component checks and failure
propagation. The complete Host/Tools policy makes three fewer Cargo observations
per target. No graph cache or new policy mode is introduced.
