# IC integration 0.74 release notes

## 0.74.0 - Unreleased

### Canonical identity and codec migration

The integration group adopts published Platform 0.15.1 and its macros/runtime
guard, canonical Types 0.15.0, and Wire/Derive 0.12.1. Tools' registry APIs retain
their facade import paths, but Principal and Account now originate from the new
Types identity. Consumers exchanging these values must align direct Platform
dependencies to 0.15.1 and rebuild together. The existing Metrics 0.23 requirement
keeps defaults disabled.

Testkit's public call limits and typed codec causes now use Wire 0.12 identity;
align direct Wire dependencies to 0.12.1. Existing query/update helpers, explicit
budgets, method identities, original error causes and no-retry policy remain.
Metrics keeps default features disabled, so its native Wire metadata does not
enter Testkit's arithmetic-only graph. Benchmark arithmetic and typed failures
retain the previously qualified contract.

Published Wire 0.12.1's optional `platform-types` integration still selects Types
0.1, so it does not implement schemas for the new Types 0.15 identities. Tooling
uses the core codec/limits and does not enable that bridge. The matching schema
adoption is still unpublished at the
[#36 — Stable Wire codec/schema identities](https://github.com/dragginzgame/ic-wire/issues/36).
The archive consumer proof checks Tooling's actual canonical registry types and
core Wire limits, with one Types identity; it makes no claim that this optional
upstream pairing works. Endpoint glue remains separate as `ic-wire-endpoint`.
Neither integration is enabled in Tooling's production graph.
The private canister probe keeps its Platform runtime and single executor owner.

### Qualification and release policy

Platform 0.15.1 restores independent runtime and Types release groups, starting
from the already published Types 0.15.0 identity. Future runtime-only patches need
not advance it; a real Types break still requires facade/schema/caller adoption.
Tooling now releases Foundation and IC integration independently within
the same qualification workspace. Integration-only changes preserve compatible
Host/Build identities and requirements. The approved boundary is tracked by
[#276 — Reduce unrelated Host and Build version churn from integration-only Tooling changes](https://github.com/dragginzgame/ic-tooling/issues/276).

The shipped Metrics arithmetic and earlier typed-call alignment are qualified in
0.73.0; [#268 — Delegate Testkit scaled benchmark averages to ic-metrics](https://github.com/dragginzgame/ic-tooling/issues/268)
and [#274 — Align Testkit typed Wire calls with the Platform 0.12-compatible Wire release](https://github.com/dragginzgame/ic-tooling/issues/274)
are closed against that published, fully qualified release. This new dependency
adoption has its own evidence and
does not inherit native macOS acceptance from an older revision.

The existing Shared runner now requires explicit `RELEASE_GROUP=integration` or
`RELEASE_GROUP=foundation`. Publication selects actual package versions, and
archive qualification no longer assumes the private driver's version applies
to every package. An opt-in consumer proof checks a candidate integration-only
minor using actual package archives and published Host/Build selections on Rust
1.91. [Release ownership](../../docs/design/release-groups.md) records membership,
commands, canonical versions, remaining public type coupling and recovery.
